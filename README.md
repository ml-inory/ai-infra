# ai-infra

研发一张 NPU PCIe 加速卡（昇腾那一类）的全技术栈学习记录。

## 技术栈总览

```
                              ▲  往 上：从芯片到能跑模型的应用
L7  分布式与集群      集合通信(HCCL/NCCL) · 多卡/多机拓扑 · 调度与切分 · 集群可观测
L6  框架与模型        PyTorch 自定义后端 · 图编译 · 推理服务与并发
L5  编译器与算子      IR/图优化 · 指令选择与调度 · 算子库 · tiling/量化/稀疏
L4  用户态运行时      上下文/流/事件 · 命令提交 · 虚拟地址空间与内存池 · 性能计数器
L3  内核与系统        设备驱动 · 统一内存与迁移 · 调度与抢占 · 虚拟化(SR-IOV/PASID/mdev) · 故障恢复
                      主机↔设备互连：PCIe/CXL 枚举 · BAR 与 MSI-X · DMA/IOMMU · P2P
L2  设备可编程模型    指令集(ISA) · 任务/图描述 · 命令队列与 doorbell · 寄存器与窗口 · DMA 引擎
                      —— 这套契约通过 BAR/MMIO 交付给主机，PCIe 只是通道之一
L1  芯片与硬件        NPU 芯粒(计算阵列/片上存储/NoC) · 片间互联(D2D) · HBM/DDR 控制器 · 时钟复位
L0  物理与工艺        先进封装(Chiplet) · SerDes 与通道 · 信号完整性 · ECC · 功耗与散热
                              ▼  往 下：从应用到能造出来的芯片
```

整个技术栈要做的，是把一块固定的硅（算力 + 存储 + 互连），以尽可能小的"税"，呈现成一个可编程、可预测的对用户可用的资源。

"税"可以归成三类，每层都是在压其中一类：

- 数据移动税：每算一个 FLOP 要搬多少字节，数据在 HBM→L2→SRAM→寄存器里穿几次。这是 NPU 最肥的一块——tiling、数据复用、融合算子全是在压它。
- 控制/同步税：一次 launch、一次 doorbell、一次中断、一次加锁往返值多少次计算。user-mode queue、batch 提交、doorbell 批处理都是在压它。
- 抽象税：虚拟化、跨进程共享、框架层拷贝、类型检查。快路径存在的意义就是让这一类税不出现在热路径上（zero-copy、dma-buf、直接映射队列内存）
