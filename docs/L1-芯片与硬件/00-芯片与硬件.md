# 芯片与硬件：把契约做成硅

> **这一层在讲什么。** [L2](../L2-设备可编程模型/00-设备可编程模型.md) 定下的契约，最终要由一块真实的硅去实现。这一层讲的就是这块硅：**算力从哪来、数据存在哪、卡与卡之间怎么连、以及为什么它不能一直跑在满速上**。
>
> **本文建立概念，不追求精确。** 想知道"这颗芯片到底多快、怎么不被宣传数字骗到"，看 [01-芯片与硬件指标](01-芯片与硬件指标.md)。
>
> **和上下层的关系。** 往下，它受 [L0 的物理与工艺](../overview.md)约束（能不能造出来、能造多大）；往上，它为 [L5 的编译器](../L5-编译器与算子/00-编译器与算子.md)和 [L6 的框架](../L6-框架与模型/00-框架与模型.md)提供可用的资源。**这一层的规格是整条技术栈的天花板**——上面的每一层优化，本质都是在"离这个天花板还有多远"上做文章。

## 一、先破除一个误解：规格上的算力不是你能用到的算力

读任何加速卡的规格页，第一件要学会的事是**分清三种"算力"**：

| 口径 | 含义 | 为什么数字好看 |
|---|---|---|
| **峰值算力（某精度）** | 硬件设计上每秒最多能做多少次运算 | 按矩阵单元满负荷、最高频率计算 |
| **稀疏算力** | 利用结构化稀疏（如 2:4）后的算力 | 跳过零元素，理论吞吐直接翻倍 |
| **实测算力** | 真实模型跑出来的有效算力 | 受数据供给、访存、并行度限制 |

**所以看到"某某卡 XXX TFLOPS"时，必须追问三件事**：哪个精度（FP4 还是 FP16？）、dense 还是 sparse、以及**在什么条件下测得**。这三个问题的答案能让同一个数字差出几倍——这也是规格页最容易误导人的地方。

**峰值算力隐含一个前提：数据能以足够快的速度送到计算单元。** 一旦送不满，算力就闲置。所以：

```
实际性能 = min(峰值算力, 访存带宽 × 算术强度)
```

这条关系（Roofline）说明了一个根本事实：**加速器不是"算力不够"，而是"算力常常在等数据"**。整条技术栈的很多工作（tiling、融合、量化、片上缓存设计）都是在解决这一个问题。

## 二、算力从哪来：计算阵列

加速卡的核心是一片**计算阵列**。按设计哲学大致分两类：

| 流派 | 思路 | 特点 |
|---|---|---|
| **脉动阵列 / 数据流架构** | 数据像流水一样穿过计算单元，每个单元只做乘加并传递 | 能效高、结构规整；**但灵活性差**，不适合非矩阵类算子 |
| **SIMT / 通用并行** | 大量可编程线程并行执行，由调度器分配 | 灵活、能跑各种算子；**但控制开销大**，能效相对低 |

实际产品往往是**混合**的：矩阵单元处理大矩阵乘（占了绝大部分算力），向量/标量单元处理归一化、激活这类"琐碎但必需"的操作。**这个结构直接决定了上一层的优化重点**——大矩阵乘能吃饱矩阵单元，而逐元素操作只能吃向量单元，两者峰值差一到两个数量级。

**数据复用是阵列设计的核心命题**：同一个数据能从存储里取出来后参与多少次计算。复用率越高，对带宽的压力越小。所以硬件上会堆多级缓冲、软件上要做 tiling——**这两件事是同一个问题的硬件解与软件解**。

## 三、数据存在哪：存储层次与 NoC

加速器内部的存储是一个**金字塔**，越靠近计算单元越快越小：

```
寄存器        ← 最快，容量最小（每个计算单元独享）
  ↓
片上 SRAM     ← 快，容量有限（用面积换带宽）
  ↓
片上缓存/L2   ← 较快，容量中等
  ↓
HBM           ← 慢得多，但容量大（几百 GB 级）
  ↓
主机内存      ← 最慢（要过 PCIe/CXL），容量最大
```

**这条链上每一层都要用"带宽"和"容量"两个数字来读**，而它们通常是反相关的：越快的越小。

**两个在这一层特别重要的概念**：

1. **片上 SRAM 是"用面积换带宽"**——它比 DRAM 快得多、也贵得多，所以容量被严格限制。**"模型装不进片上存储"是常态**，这正是 tiling 存在的原因。
2. **bank 冲突**：片上 SRAM 被划分成多个可并行访问的 bank。如果访问模式不好，多个访问落在同一个 bank 上，就会串行化——**带宽实际利用率远低于峰值**。这是"布局变换"这类优化的硬件动机。

**NoC（片上网络）**是把这些存储与计算单元连起来的"片上总线"。**它常常是隐形瓶颈**：算力可以靠堆矩阵单元线性增长，但片上带宽的增长要难得多——所以"算力堆上去了、片上供不上数据"是常见现象。

## 四、HBM：为什么加速卡必须用它

大模型需要**极高的访存带宽**，这是 HBM（高带宽内存）存在的唯一理由。

它的做法很直接：**把内存芯片一层层堆起来，用极宽的接口连到处理器**。堆叠带来两个好处：

- **位宽极大**（比普通内存宽一个数量级），于是带宽极高；
- **物理距离极近**，于是功耗更低、能跑更高频率。

**HBM 的带宽是可以算出来的**，这是这一层少有的"确定性公式"：

```
HBM 带宽 ≈ 单 stack 位宽 × 数据率 × stack 数量
```

**容量则由堆叠层数决定**——层数越多容量越大，但**层数受封装厚度与散热限制**。这就是为什么 HBM 容量的提升总是慢于算力的提升：**算力可以靠堆单元，容量要靠堆物理层**。

**ECC 在 HBM 上是必需的**：数据中心设备不能容忍静默数据错误。ECC 要么用额外容量换（牺牲一部分容量），要么靠专门的校验机制。这也是为什么"标称容量"与"可用容量"常常不等。

## 五、卡与卡之间：D2D 互联与一致性

单卡算力有上限，所以要把多张卡连起来。**互联的带宽与拓扑，直接决定了 [L7 的扩展效率](../L7-分布式与集群/01-集群评测.md)**。

**芯粒（chiplet）路线**是近年最重要的变化：不再强求把整个芯片做成一块大硅片，而是**把若干小芯粒封装在一起**，芯粒之间用高速接口（D2D）连接。这样做的动机有三个：

1. **良率**：大芯片的良率随面积急剧下降，小芯粒良率高得多；
2. **工艺搭配**：计算部分用最先进工艺，I/O 部分用成熟工艺，各取所需；
3. **复用**：同一套 I/O 芯粒可以配不同规模的算力芯粒。

**代价是多了一层"芯粒间通信"**：芯粒之间的带宽与延迟不可能等于片内，所以**算力切分方式会影响性能**——这也是为什么并行策略（[L7](../L7-分布式与集群/00-集群是什么.md)）必须知道硬件的互联拓扑。

**一致性**是另一个关键问题：CPU、多张加速卡、以及卡内的多个芯粒，各自有缓存。**"谁看到的数据是对的"**必须有明确机制来保证，否则并行程序会读到过期数据。这也是为什么高速互联标准（如 CXL）把"缓存一致性"当作核心卖点之一。

## 六、拷贝引擎：为什么不能只靠计算单元搬数据

数据从主机到设备、设备内不同存储之间移动，需要**专门的拷贝引擎（DMA）**。它存在的理由：

- **让计算单元专注计算**：如果让矩阵单元去搬数据，就是拿最贵的资源做便宜的事；
- **能并行**：拷贝引擎与计算单元可以同时工作（这正是 [L4 的"重叠"](../L4-用户态运行时/00-用户态运行时.md)在硬件上的基础）；
- **能走更宽的路径**：拷贝引擎可以按 HBM 的位宽满速搬，而计算单元的访存受限于它的加载通路。

**但"拷贝"本身是纯开销**：每搬一次数据就消耗一次带宽，而带宽是这一层最贵的资源之一。所以上层的一切"零拷贝""融合""数据复用"优化，本质都是在**减少拷贝次数**。

---

## 七、时钟、功耗与热：为什么不能一直满速

最后一个约束来自物理：**芯片不能一直跑在最高频率上**。原因链条是：

```
频率越高 → 电压要越高 → 功耗随电压平方增长、随频率线性增长
        → 发热增加 → 温度上升 → 漏电增加 → 要么降频、要么烧毁
```

于是硬件提供了**动态调节机制（DVFS）**：根据负载与温度调整电压和频率。**对上层来说，这意味着"性能不是常数"**：

- 同一条代码，在冷机与热机下可能差出可观的比例；
- 大规模训练时，"功耗墙"与"温度墙"会成为真实约束——**这也是为什么液冷在整柜方案里是必需而不是加分项**。

**这一层还有一个容易被忽略的事实**：**空闲也耗电**。静态功耗（漏电）随温度上升而增加，所以"卡闲着"并不等于"不耗电"，这在集群成本核算（[L7 的 $/百万 token](../L7-分布式与集群/01-集群评测.md)）里是真实成本。
