# 02 · 芯片设计：从单个 PE 到 4 芯粒

> **这份文档是什么。** [00](00-芯片与硬件.md) 讲这一层的概念、[01](01-芯片与硬件指标.md) 讲怎么量、[连接与指标](../connections-and-metrics.md) 给跨层框架。**这一份做决定**：NPU4 的微架构、存储层次、芯间互联、以及与 [L2 契约](../L2-设备可编程模型/02-契约设计.md) 的接口。
>
> **本文面对的第一个问题不是"怎么设计"，而是"现有的东西和目标差多远"。** 仓库里已经有 [mini_npu](../../mini_npu/doc/ip_design.md)——一个 4×4 广播式 MAC 阵列 + AXI4-Lite + 三块 SRAM 的**单芯粒** IP。而 L2 契约定的是 **4 芯粒、6 条 D2D、12 条队列**。**这两份设计之间有一段真实的距离**，本文要把它量化清楚，而不是含糊过去。

## 一、现状盘点：我们手里有什么

### 1.1 三层现实

| 层 | 状态 | 内容 |
|---|---|---|
| **已验证** | 【已实现】 | `PE`：8×8 有符号乘加 + 32 位累加；`pe_tb.sv` 34 条向量 |
| **已设计未实现** | 【已设计】 | `mini_npu v1`：4×4 阵列、三块 SRAM、AXI4-Lite 从端、12 个寄存器、电平中断、序列器 FSM |
| **只有目标** | 【本文新增】 | 4 芯粒、6 条 D2D、与 L2 的 12 条队列对接 |

**必须承认的一件事**：从【已实现】到【本文新增】，中间隔着两次质变——**阵列化**（1 → 16 个 PE）和**多芯粒化**（1 → 4 芯）。**本文只详细设计第二次质变中"芯片侧"的部分**，阵列化的规格沿用 `mini_npu v1` 的设计。

### 1.2 `mini_npu v1` 的关键参数（本层的基线）

**从 [ip_design.md](../../mini_npu/doc/ip_design.md) 摘录**，这些是后续设计的起点：

| 项 | v1 取值 |
|---|---|
| 阵列 | 4×4 = **16 个 PE**（参数化） |
| 精度 | A/W **8 位有符号**，累加 **32 位有符号**，无饱和 |
| 片上存储 | **三块 1W1R SRAM**：`ACT`(1024×32) / `W`(1024×32) / `OUT`(16×32) |
| 数据入口 | **CPU 逐字 `writel`**（无 DMA、无描述符） |
| 总线 | AXI4-Lite 从端，单笔未完成，32 位 |
| 中断 | 一根电平线 |
| 时钟 | **单时钟域**，无 CDC |
| 任务粒度 | **一次任务 = 一个 tile**（M≤4、N≤4、K≤1024） |

### 1.3 v1 的性能真相（作者自己算的，值得尊重）

设计文档里有一段很诚实的自评，本文直接采用并把它的含义推到目标设计：

| 事实 | 数字 |
|---|---|
| 一次 4×4×K 任务的拍数 | `3 + 2K + 16`，K=4 时约 **27 拍** |
| 计算量 | 64 MAC |
| 理想拍数（16 PE 并行） | 4 拍 |
| **PE 利用率** | **约 15%** |
| 低效的两个原因 | ① `LDW`/`MAC` 分离（每步 2 拍，直接砍半）② 固定开销 19 拍（检查 1 + 清零 1 + 排空 16 + 完成 1） |
| **更严重的瓶颈** | **数据靠 CPU 逐字写**：K=1024 要写 2048 个字，约 4000–6000 拍，**比计算（约 2067 拍）还慢** |

**最后一条是本层最重要的结论**：`mini_npu v1` **不是算力受限，而是数据供给受限**——这正是 [README](../../README.md) 所说的"数据移动税"，而且是在最粗的粒度上（CPU 逐字搬运）。

**本文的一切设计决定都要回答一个问题：怎么把这条搬运路径换掉。**

## 二、四个设计决定

### 2.1 决定一：芯粒划分用"同构 4 芯"而不是异构

**决定**：**4 个完全相同的计算芯粒**，每个都是"阵列 + 片上存储 + D2D 接口"的完整实例，**不设专门的 I/O 芯粒**。

| 方案 | 优点 | 缺点 |
|---|---|---|
| **同构 4 芯**（选定） | 一份 RTL 实例化 4 次；良率与设计复用都最好 | 主机接口（PCIe）要在 4 个芯粒里选一个或复制，略浪费 |
| 异构（1 个 I/O 芯粒 + 3 个计算芯粒） | 接口资源不重复 | 需要两种 RTL；I/O 芯粒成为单点故障与瓶颈 |

**为什么选同构**：从 [L0 的良率模型](../L0-物理与工艺/01-工艺与物理指标.md)看，**同构意味着只需要验证与维护一套芯粒设计**——4 个不同芯粒的验证成本是 4 倍，而 4 个相同芯粒只是实例化 4 次。在良率上，同构也更容易做"哪些芯粒是好的"这类筛选与降级（3 芯可用就按 3 芯卖）。

**代价与应对**：PCIe 端点**只在一个芯粒上实例化**（定为芯粒 0），其余 3 芯通过 D2D 访问它暴露的主机接口。这条要写进 L2 的队列归属（见 §5）。

### 2.2 决定二：D2D 的语义选"内存语义"而不是"消息语义"

**这是本项目最关键的架构决定。**

| 方案 | 含义 | 对上层的影响 |
|---|---|---|
| **内存语义**（选定） | 每个芯粒有一片**对其它芯粒可见的地址空间**，跨芯访问就像访问本地内存，只是慢一些 | **对软件透明**：切分策略不必显式发消息 |
| 消息语义 | 芯粒之间显式收发消息，由软件/固件管理 | 软件复杂度高；但可以精细控制通信 |

**为什么选内存语义**：它**让 L2 契约不必为跨芯访问增加新的命令类型**。回想 L2 的决定——**4 芯全互联是为了让"设备地址"保持简单**（[L2 §2.2](../L2-设备可编程模型/02-契约设计.md)），内存语义正是这条决定的自然延伸：既然全互联让任意芯粒互相等价，那么用同一套地址空间描述它们就是自洽的。

**代价（必须量化）**：

```
跨芯访问的代价 = 额外的 D2D 链路延迟 + 可能的带宽竞争
```

**这就要求 D2D 带宽足够高**，否则"内存语义"会变成"看起来很优雅但很慢"。**§4 会给出这笔账。**

### 2.3 决定三：数据入口从"CPU 逐字写"换成"DMA 描述符"

**决定**：引入 **DMA 引擎**，数据由设备自己从主机内存搬进片上 SRAM。这直接对应 L2 契约里的 **DMA 队列**（队列 1/4/7/10）。

**为什么这是必须的**（不是优化，是补救）：`mini_npu v1` 的性能瓶颈就是这条路径——CPU 搬运比计算还慢。**换掉它，PE 利用率才有意义**。

| 项 | v1 | 目标 |
|---|---|---|
| 数据入口 | CPU `writel` 逐字 | **DMA 描述符**（L2 契约的分散聚集格式） |
| 谁来搬 | CPU（占 CPU、占总线） | DMA 引擎（与计算重叠） |
| 搬运与计算的关系 | 严格串行 | **可重叠**（这正是"重叠率"要压的东西） |

### 2.4 决定四：片上存储从"三块绑定端口"扩成"分层 + 可仲裁"

`mini_npu v1` 的三块 SRAM 有一个很聪明的简化：**端口归属固定，因此全设计零仲裁**。但引入 DMA 之后这个简化会破：

- 原来 `ACT_SRAM` 只有"CPU 写、序列器读"；
- **现在 `ACT_SRAM` 变成"DMA 写、序列器读"**，而 `OUT_SRAM` 变成"序列器写、DMA 读"——**端口归属仍然固定**，所以**零仲裁这个优点可以保住**。

**这是一个重要的发现**：**DMA 替换 CPU 并不破坏 v1 的结构美**，因为 DMA 只是换了一个"写 ACT / 读 OUT"的主体，端口归属依然唯一。

| SRAM | v1 的写方 | 目标的写方 | v1 的读方 | 目标的读方 | 仲裁 |
|---|---|---|---|---|---|
| `ACT` | CPU | **DMA** | 序列器 | 序列器 | 无 |
| `W` | CPU | **DMA** | 序列器 | 序列器 | 无 |
| `OUT` | 序列器 | 序列器 | CPU | **DMA** | 无 |

**但容量要重新算**：v1 的 1024 字深是"CPU 写得动"的规模。换成 DMA 后，**深度应由"一次任务能覆盖多大 tile"决定**，而这是 L5 tiling 的输入（见 [连接与指标 §六](../connections-and-metrics.md) 的 L5↔L1 检查项）。

**本文给出待定的形式**（而非拍一个数字）：

```
ACT_DEPTH 由三者共同约束：
  ① 一次任务的最大 K（序列器循环上界）
  ② tile 的 M×K 打包后需要多少字（v1 是 M 个 8 位打包进 1 个 32 位字）
  ③ 片上面积预算（L0 的 SRAM 密度决定）
```

## 三、微架构

### 3.1 一个芯粒的框图（目标形态）

```
        ┌──────────────────── 芯粒 0（含主机接口） ────────────────────┐
        │                                                              │
  PCIe ─┤ 主机接口 ──► 队列/DMA 引擎 ──► ACT/W SRAM ──► PE 阵列        │
        │   (L2 契约)      │                    ▲            │          │
        │                  │                    │            ▼          │
        │                  └──► OUT SRAM ◄──────┴──── 序列器             │
        │                                                              │
        │              D2D 链路 × 3（到芯粒 1/2/3）                      │
        └──────────────────────────────────────────────────────────────┘

        ┌──────────── 芯粒 1/2/3（纯计算） ────────────┐
        │  D2D 链路 × 3 ──► 本地 SRAM ──► PE 阵列      │
        │                     ▲              │         │
        │                     └── 序列器 ◄───┘         │
        └──────────────────────────────────────────────┘
```

**芯粒 0 与其它芯粒的唯一差别是"有没有 PCIe 端点"**——RTL 上通过参数 `IS_HOST_DIE` 区分，**不产生两套设计**。

### 3.2 存储层次（四层，与 [00 §三](00-芯片与硬件.md) 的通用金字塔对应）

| 层 | 本项目对应 | 带宽量级 | 说明 |
|---|---|---|---|
| **寄存器** | PE 内部 `w_inner`、`psum` | 最高 | 每 PE 独享 |
| **片上 SRAM** | `ACT`/`W`/`OUT` | 高 | v1 每拍各读 1 个字（32 位） |
| **本地 HBM** | 芯粒本地显存 | 中 | **v1 里不存在**（用主机内存代替） |
| **远端（跨芯/主机）** | D2D / PCIe | 最低 | 本文与 L2/L3 的交界 |

**一处必须在 L1 层就算清的账：PE 阵列的带宽需求。**

```
16 个 PE，每拍每个 PE 需要 1 个激活 + 1 个权重（8 位各一）
  ⇒ 阵列每拍需要 16 × 8 × 2 = 256 位 = 32 字节/拍
而 v1 的实现是：每拍从 ACT 读 32 位 + 从 W 读 32 位 = 8 字节/拍
  ⇒ 带宽差 4 倍
```

**这解释了 v1 那个"15% 利用率"里的另一半原因**：`LDW`/`MAC` 分离让每步变 2 拍（砍半），而**阵列的供给带宽只有需求的 1/4**——两者叠加正好接近观察到的数字。

**结论（给 L1 的指标）**：**要让 16 个 PE 满负荷，片上 SRAM 的读取带宽必须提高 4 倍**（要么加宽字、要么多端口、要么改变阵列的时序模型）。**这是 L1 内部最该先解决的问题，比加 PE 数量更优先。**

> 这条与 [连接与指标](../connections-and-metrics.md) 的 L5↔L1 检查项直接对应：**L5 想切多大 tile，取决于 L1 能供多少带宽**。现在这个数是"每拍 8 字节"，**它是 L5 tiling 的硬上界**。

### 3.3 时钟与复位

| 项 | v1 | 目标 | 说明 |
|---|---|---|---|
| 时钟域 | 单域 | **每芯粒一个核心域 + D2D 一个域** | 芯粒间必须跨域（物理上不同 die） |
| CDC | 无 | **D2D 接口处必须做 CDC** | 这是 v1 → 目标最大的结构性变化 |
| 复位 | 异步置位/同步释放 | 同 v1 + **芯粒级独立复位** | 对应 L2 契约的错误分级（[L2 §6.2](../L2-设备可编程模型/02-契约设计.md)） |

**CDC 是本层新增的最大工程风险**：v1 明确写"单时钟域，不存在 CDC"是它简化的基础之一。引入 D2D 之后**这个简化消失**，而 CDC 的验证成本远高于功能验证（需要专门的 CDC 检查工具，v1 明确列在"不做"里）。

> **诚实标注**：CDC 检查**不在本项目现有工具链的能力范围内**（v1 的交付清单里 CDC/DFT/覆盖率都标了"不做"）。所以**D2D 接口的实现可以有，但它的时序正确性无法在当前环境验证**——这是一个必须记录的限制。

## 四、芯间互联：6 条链路的账

### 4.1 为什么是 6 条

按 [L2 §2.2](../L2-设备可编程模型/02-契约设计.md) 的决定，4 芯**全互联**（不是环）：

```
4 个节点两两相连 = C(4,2) = 6 条链路
```

**为什么全互联划算**：4 个节点时链路数只有 6 条，而**它换来的是"任意芯粒互相等价"**——不需要在地址里表达路径，也不需要路由表。

### 4.2 链路分层（借鉴开放芯粒互连规范的思路）

公开的芯粒互连标准把接口分成物理层 / 协议层 / 软件栈（见 [00 §五](00-芯片与硬件.md)）。**本项目只实现前两层的简化版**：

| 层 | 本项目 | 依据 |
|---|---|---|
| **物理层** | 简化为"并行数据 + 握手"，不实现 SerDes | 仿真环境不做电气模型 |
| **协议层** | 自定义的**简单转发协议**：读请求 / 写请求 / 应答 | 见 §4.3 |
| **软件栈** | **不需要**——内存语义对上透明 | §2.2 的直接后果 |

**这个"不需要软件栈"是内存语义的最大红利**：消息语义必须定义消息格式、顺序、错误处理；内存语义把这些都压进了"读写远程地址"这一件事。

### 4.3 协议最小集

为了让仿真可实现，协议只定义三种事务：

| 事务 | 字段 | 说明 |
|---|---|---|
| **读请求** | 源芯粒、目标地址、长度 | 请求远端数据 |
| **写请求** | 源芯粒、目标地址、长度、数据 | 写远端内存 |
| **应答** | 事务 ID、状态 | 完成通知 |

**顺序语义（必须定死，否则是 bug 温床）**：

```
同一源→同一目标：保序（先发的先到）
不同源→同一目标：不保证顺序
```

**为什么这样定**：保序只需要每对芯粒之间一个简单的有序队列；而全局保序需要集中仲裁，代价大且不必要——**上层用 fence 表达真正的依赖**（这与 [L2 的完成语义](../L2-设备可编程模型/02-契约设计.md) 是同一套思路：把顺序责任明确到某一层，而不是到处都保证）。

### 4.4 D2D 带宽：本项目的枢纽指标

**这是 L1 唯一"直接决定 L7"的指标**（[连接与指标 §2.3](../connections-and-metrics.md)）：

```
扩展效率 = 1 − 通信时间 ×(1 − 重叠率) ÷ 总时间
其中 通信时间 = 每步通信量 ÷ D2D 有效带宽
```

**有效带宽的算法**（与 [L0 的链路指标](../L0-物理与工艺/01-工艺与物理指标.md) 一致）：

```
D2D 有效带宽 = lane 速率 × lane 数 × 编码效率 × 链路数
```

**注意最后一项**：**6 条链路不等于 6 倍带宽**——只有在"4 个芯粒同时两两通信"的极端情况下才能全部用上。**实际可达带宽取决于并行策略**（这正是 L7 要回答的）。

**本文给出待定的形式**（不拍数字）：

```
D2D 目标带宽 ≥ (每步通信量 × (1 − 重叠率)) ÷ 可接受的通信时间占比

其中"每步通信量"由 L7 的切分策略给出 —— 这是 L1↔L7 反馈回路的输入端
```

> **这条式子是本文与 L7 的接口**。L7 的 02 必须先给出切分策略与每步通信量，L1 才能回填 D2D 带宽目标——**而 L1 定了带宽之后，L7 要重算扩展效率**。这就是 [连接与指标 §7.3](../connections-and-metrics.md) 说的那条反馈回路。

## 五、与 L2 契约的接口：三处必须对齐的地方

### 5.1 对齐一：队列归属 ↔ 芯粒编号

L2 契约把 12 条队列按芯粒划分（[L2 §3.3](../L2-设备可编程模型/02-契约设计.md)）：

| 队列 | 归属 |
|---|---|
| 0/3/6/9 | 芯粒 0–3 的**计算队列** |
| 1/4/7/10 | 芯粒 0–3 的 **DMA 队列** |
| 2/5/8/11 | 芯粒 0–3 的**控制队列** |

**L1 侧要提供什么**：每个芯粒一个"队列前端"（解析描述符、触发本地序列器），**队列内存位于主机内存**，由 DMA 引擎读取。

**一处需要澄清的地方**：芯粒 1/2/3 的队列内存也在主机内存里，但它们**没有 PCIe 端点**——所以它们的队列访问**必须经芯粒 0 转发**。

```
芯粒 1 的队列在主机内存
   → 芯粒 1 的 DMA 引擎发起读
   → 但只有芯粒 0 有 PCIe
   → 所以请求经 D2D 到芯粒 0，由它代理 PCIe 读
   → 数据再经 D2D 回到芯粒 1

代价：一次跨芯队列读取 = 2 次 D2D 传输 + 1 次 PCIe
```

**这是同构设计 + 单 PCIe 端点的直接后果**，必须在 L1 里显式实现"主机访问代理"，并在 L3/L4 里考虑它的延迟影响。

> **替代方案（记录但不选）**：给每个芯粒都做一个 PCIe 端点 → 4 个端点需要 4 组 SerDes，**在 6nm 的功耗与面积下不划算**（[L0 的功耗与散热](../L0-物理与工艺/00-物理与工艺.md)）。所以代理方案是当前约束下的合理选择。

### 5.2 对齐二：doorbell 覆盖量（L2 的 TBD 之一）

L2 契约把 `CAP1[15:0]`（doorbell 单次覆盖的最大命令数）标为 `TBD`，等 L1 回填。**L1 的约束来自哪**：

```
doorbell 覆盖量 ≤ 队列深度（L2 的 CAP0）
且 ≤ 序列器一次能连续取指并派发的任务数
```

**本文的结论**：**这个值应该等于队列深度**——因为"一次通知让设备取走所有可用命令"是最自然的语义，**没有理由人为设一个更小的上限**。

**但要加一条约束**：如果一次覆盖太多，设备可能长时间不回中断（聚合效应）。所以：

```
CAP1 = 队列深度上限
但配套要求：每处理完一个任务链就必须检查是否该发中断（不能攒到全部做完）
```

**这条约束要写进 L1 的序列器与 L2 的中断配置**（两边都要）。

### 5.3 对齐三：窗口数（L2 的另一个 TBD）

L2 契约有 **8 个窗口寄存器**，标为 `TBD`。**L1 侧的实际需求**：

| 需要被窗口映射的地址空间 | 数量 |
|---|---|
| 芯粒 0–3 各自的本地 SRAM | 4 |
| 芯粒 0–3 各自的本地 HBM 段 | 4 |
| **合计** | **8** |

**结论：8 个窗口正好够**——每个芯粒的 SRAM 与 HBM 各占一个窗口。**所以 L2 的窗口数不需要改**，只是现在有了依据。

> **这条对账很有价值**：L2 当初给 8 个窗口是按 `4 芯 × 2 段` 估的，**现在 L1 的地址空间结构证实了这个数**。这是"跨层一致性检查"起作用的例子。

## 六、性能模型：诚实地量化每一层瓶颈

### 6.1 从 v1 到目标的瓶颈迁移

| 版本 | 主要瓶颈 | 依据 |
|---|---|---|
| **v1**（已设计） | **数据供给**（CPU 逐字写：4000–6000 拍 vs 计算 2067 拍） | v1 自评 |
| **v1 + DMA** | 片上带宽（每拍 8 字节 vs 需求 32 字节） | §3.2 的账 |
| **v1 + DMA + 加宽 SRAM** | **D2D 带宽**（跨芯通信） | §4.4 |
| **再加芯粒/加 PE** | 回到片上带宽或 D2D（取决于切分） | 待 L7 给出切分策略 |

**这张表的用法**：**每解决一个瓶颈，下一个就会浮现**——所以"优化"不该是盲目的，而应该先确认"当前瓶颈在哪一层"。这就是 [连接与指标 §2](../connections-and-metrics.md) 因果分解的实用价值。

### 6.2 可算的几条（现在就能算）

| 指标 | 算法 | 现在能否算 |
|---|---|---|
| PE 阵列的带宽需求 | `PE 数 × 操作数位宽 × 2 ÷ 每拍时钟` | ✅ **能**（= 32 B/拍） |
| 片上 SRAM 现有带宽 | `字宽 × 端口数` | ✅ **能**（= 8 B/拍） |
| 带宽缺口 | 需求 ÷ 现有 | ✅ **能**（= **4 倍**） |
| 单芯理论算力 | `PE 数 × 2 × 频率` | ✅ **能**（缺频率与 PE 数目标） |
| D2D 有效带宽 | `lane 速率 × lane 数 × 编码效率 × 链路数` | ⏳ 待 L0 选型 |
| 扩展效率 | 依赖 L7 的切分策略 | ⏳ **待 L7 的 02** |
| 能效（TFLOPS/W） | — | ❌ **【需真硅】** |

**注意最后一行**：按 [连接与指标](../connections-and-metrics.md) 的约定，**能效是【需真硅】指标**，本设计里只能给目标值，不能声称已达成。

### 6.3 一处必须记录的"不可验证项"

**CDC 与时序收敛**：本项目用 Icarus Verilog 做功能仿真（[sim/README](../../mini_npu/sim/README.md)），**它不检查跨时钟域问题，也不做时序分析**。

所以引入 D2D 后的多时钟域设计：

- **功能可以在仿真里验证**（只要 CDC 逻辑写得对）；
- **时序与亚稳态无法在当前环境验证**——这需要 CDC 检查工具与综合/STA，**都不在现有工具链里**。

**这条要写进 L1 的已知限制**，否则会给人"多芯粒设计已验证"的错觉。

## 七、参数化与 RTL 结构

### 7.1 继承与新增的参数

| 参数 | 来源 | 默认 | 说明 |
|---|---|---|---|
| `R` / `C` | v1 | 4 / 4 | 阵列维度 |
| `A_BITS` / `W_BITS` | v1 | 8 / 8 | 操作数位宽 |
| `ACC_BITS` | v1 | 32 | 累加位宽 |
| `ACT_DEPTH` / `W_DEPTH` | v1 | 1024 | 片上存储深度（**目标要重算**） |
| **`DIE_COUNT`** | **本文新增** | **4** | 芯粒数 |
| **`IS_HOST_DIE`** | **本文新增** | **芯粒 0 = 1，其余 = 0** | 是否有 PCIe 端点 |
| **`D2D_LANES`** | **本文新增** | TBD | 每条链路的位宽 |
| **`D2D_CDC_STAGES`** | **本文新增** | 2 | 跨域同步级数 |

### 7.2 模块层次（在 v1 之上新增的两块）

```
npu_die.sv                      ← 芯粒顶层（v1 的 npu_top 改名并扩展）
├── npu_regs.sv                 【v1 已设计】寄存器 + AXI4-Lite + 中断
├── npu_seq.sv                  【v1 已设计】序列器
├── pe_array.sv                 【v1 已设计】4×4 阵列
├── sram_dp.sv ×3               【v1 已设计】三块 SRAM
├── dma_engine.sv               ← 【本文新增】替代 CPU 逐字写
├── queue_front.sv              ← 【本文新增】解析 L2 描述符、触发序列器
└── d2d_port.sv  ×3             ← 【本文新增】D2D 协议 + CDC

npu_chip.sv                     ← 【本文新增】4 个 die 的互连（仿真用）
└── npu_die.sv ×4 + 6 条 D2D 链路
```

**`npu_chip.sv` 是仿真专用**：在真实芯片上，4 个 die 之间的连接是封装的物理走线，不由 RTL 描述。但**仿真里必须有它**，否则无法验证 D2D 协议与多芯协作。

> **这一层是"仿真专用顶层"，与"可综合 RTL"必须分开**：`npu_chip.sv` 里会有理想化的链路模型（零延迟或固定延迟），**它不是可综合的**。这个边界要在文件头注明，避免被误当作设计的一部分。

### 7.3 与 v1 的兼容性

**v1 的 PE 与 tb 保持不动**（v1 文档明确要求"保持不动，作为回归"）。新增模块**不修改 `pe.sv` 与 `pe_tb.sv`**。

**这意味着**：v1 里那个"用 `rst` 兼职清累加器"的权宜做法（[v1 §10.2](../../mini_npu/doc/ip_design.md)）**继续保留**——因为改它就要动 PE。**这是有意的取舍**：先保住已验证的回归基线，把设计债留在一个明确记录的位置。

## 八、这一层的验收条件

按 [连接与指标 §五](../connections-and-metrics.md) 的"目标值 + 测量方法 + 判定"写法：

| # | 指标 | 测量方法 | 判定条件 |
|---|---|---|---|
| 1 | **片上带宽是否够** | `PE 数 × 位宽 × 2` 对比 `SRAM 字宽 × 端口` | **需求 ≤ 供给**，否则 PE 必然闲置（当前差 4 倍） |
| 2 | **D2D 有效带宽** | `lane 速率 × lane 数 × 编码效率 × 链路数` | 必须**能代入 L7 的扩展效率公式**并得出 > 0 的余量 |
| 3 | **D2D 保序语义** | 仿真：同源同目标连续发 N 笔，检查到达顺序 | 同源同目标**严格保序**；不同源**不保证**（符合 §4.3） |
| 4 | **跨芯队列代理路径** | 仿真：芯粒 1 发队列请求，走代理到芯粒 0 | 数据正确且**路径可观测**（延迟可测，虽然是仿真的理想模型） |
| 5 | **芯粒级复位** | 仿真：复位芯粒 2，检查其余 3 芯继续工作 | 其余芯粒的队列与任务**不受影响**（对应 L2 的错误分级） |
| 6 | **参数化可综合** | 用新参数值重新 elaborate | 编译期断言全部通过（继承 v1 的六条断言） |
| 7 | **CDC（不可验证项）** | — | **明确记录为当前环境无法验证**，不给"已验证"的声明 |

**最该先做的一条是第 1 条**：它是纯算术，**现在就能算**，而且算出来的结论（差 4 倍）**直接决定 L5 的 tiling 上限**。

## 九、本文的边界与下一步

### 9.1 本文明确不做的

| 不做的事 | 理由 |
|---|---|
| SerDes 电气模型 | 仿真环境不做电气层（[L0](../L0-物理与工艺/00-物理与工艺.md) 的范围） |
| CDC 与时序收敛验证 | 现有工具链（Icarus Verilog）不具备该能力 |
| HBM 控制器 | 项目约束下用主机内存替代；HBM 属后续版本 |
| 卡间互联 | **项目约束明确不做** |
| 能效测量 | 【需真硅】 |

### 9.2 下一步的顺序

```
① 先算清片上带宽（本文 §3.2 已给出结论：差 4 倍）
      ↓ 这是 L5 tiling 的硬上界
② L7 的 02：给出切分策略与每步通信量
      ↓ 这是 L1 回填 D2D 带宽目标的输入
③ L1 回填 D2D 带宽（并回头让 L7 重算扩展效率 —— 反馈回路）
      ↓
④ L3/L4 的 02：按 L2 契约实现队列代理、doorbell 令牌、六条数据路径
      ↓
⑤ L5/L6 的 02：按 L1 的带宽上界做 tiling，按 L2 的粒度做提交
      ↓
⑥ L0 的 02：按最终的算力与 D2D 规格算功耗、散热、良率与成本
```

**注意 ②③ 是一个循环**：L7 给通信量 → L1 定带宽 → L7 重算效率。**这个循环可能要走两轮才收敛**，要在计划里预留。
