# 芯片与硬件指标：口径、带宽与能效

> **这一层在讲什么。** [00-芯片与硬件](00-芯片与硬件.md) 讲清楚了算力、存储、互联、功耗这四件事；这篇回答**怎么读、怎么核算、怎么不被规格数字骗到**。
>
> **读法。** 只想知道"概念"，读完 00 就够；要做选型、要核对一份规格页、要判断某块卡的宣传数字是否可信，再往下读这篇。
>
> **和 L5 的分工。** [L5 的指标](../L5-编译器与算子/01-编译与算子指标.md)看的是"**用到了峰值的百分之几**"；这一层定义的是**那个"峰值"本身到底是什么**。**分母错了，分子算得再准也没意义**——这就是为什么这一层要先讲口径。

## 一、第一件事：把算力的口径拆开

**规格页上的算力是这一层最容易被误读的数字**，因为它至少有三层缩水空间：

| 层次 | 含义 | 典型缩水来源 |
|---|---|---|
| **标称峰值** | 按矩阵单元满负荷 × 最高频率算 | 假设数据永远供得上 |
| **可达峰值** | 考虑频率/功耗约束后的持续峰值 | 实际跑不到最高频率 |
| **实测有效** | 模型跑出来的算力 | 受访存、并行度、算子形态限制 |

**核对一个算力数字，要问四个问题**：

1. **哪个精度？** FP4 / FP8 / FP16 / BF16 的算力差距是成倍的——低位宽矩阵单元每周期能处理更多元素。
2. **dense 还是 sparse？** 结构化稀疏（如 2:4）通过跳过零元素，常被用来报出"翻倍"的数字。**你跑的不是稀疏模型，就用不到这个数字。**
3. **是否含"加"还是只算"乘加"？** 不同厂商的 FLOPs 统计口径可能不同（一次乘加算 1 次还是 2 次运算）。
4. **在什么频率下？** 标称峰值通常基于最高加速频率，而实际持续频率受功耗与温度约束。

**实操建议**：把规格页上的数字当作**上限**而不是**预期**。真正有意义的对照是"同一精度、同一 dense/sparse 口径、能持续跑住的算力"。

## 二、带宽：这一层最该算清楚的数

**带宽往往比算力更能决定实际性能**（因为算力常在等数据）。而带宽也是规格页里**最少被虚标、最容易自己核算**的数字——这一层少有的可以精确验证的地方。

### 2.1 显存带宽是可以算出来的

```
显存带宽 = 单 stack 位宽 × 数据率 × stack 数量
```

**为什么这个公式可信**：位宽由接口物理设计决定，数据率由标准代际决定，stack 数量是物理堆叠的数量——三者都是明确可查的。**拿到位宽与数据率就能验算**，不需要相信任何营销口径。

一个有用的推论：**显存带宽的提升靠"加宽接口"和"提高数据率"两条路**，而加宽接口需要更多堆叠、更多走线，受封装限制；提高数据率受信号完整性限制。**这解释了为什么带宽增长比算力增长慢**——也正是"算力在等数据"这个结构性问题的根源。

### 2.2 要区分三种带宽

| 带宽 | 走什么路径 | 量级关系 |
|---|---|---|
| **片上带宽** | SRAM ↔ 计算单元 | 最高，但常被"数组单元素复用"限制 |
| **显存带宽** | HBM ↔ 芯片 | 高，是这一层的主战场 |
| **主机链路带宽** | 主机 ↔ 设备（PCIe/CXL） | **低一个数量级以上** |

**最后一条尤其重要**：主机链路带宽比显存带宽低一到两个数量级。所以**"数据尽量留在设备上"不是优化技巧，而是物理约束下的必然选择**。这也解释了为什么 [L4](../L4-用户态运行时/00-用户态运行时.md) 里"重叠率"这么关键——主机链路是慢的，必须藏起来。

### 2.3 有效带宽与标称带宽的差距

标称带宽是理论上限，实际能达到的比例受访问模式影响：

- **连续大块访问**能接近峰值；
- **随机/碎片化访问**会明显掉下来（DRAM 的行激活开销）；
- **bank 冲突**（片上 SRAM）会让多个访问串行化。

所以**评估"带宽够不够"时，要用实际访问模式下的有效带宽，而不是标称带宽**。

## 三、容量：一个"不达标就全盘失效"的指标

容量不像带宽那样是渐变的——**装不下就是装不下**，没有中间状态。所以要算三项之和：

```
显存需求 = 模型权重 + KV cache + 激活与临时缓冲 + 框架开销
```

**三个容易低估的部分**：

1. **权重要按精度算**：同模型用 FP8 存比 BF16 省一半，用 FP4 再省一半——**精度选择首先是容量决策**。
2. **KV cache 随并发 × 上下文长度线性增长**：长上下文推理时它可能超过权重本身，是容量的真正约束。
3. **"标称容量"不等于"可用容量"**：ECC、系统保留、框架预留都会占掉一部分。规格页给出的"可用"数字才是有意义的。

**判断方法**：先算"最少需要多少容量"，再对照**可用容量**，留出安全余量。**装不下的后果不是变慢，而是根本跑不起来**——所以这项该在选型第一步就排除。

## 四、D2D 与互联带宽：决定扩展上限

多卡场景下，**卡间互联带宽决定了扩展效率的上限**（见 [L7 的扩展效率实测](../L7-分布式与集群/01-集群评测.md)）。要区分三档：

| 层级 | 范围 | 带宽量级 |
|---|---|---|
| **片内** | 同一芯粒内部 | 最高 |
| **D2D / 芯粒间** | 同一封装内的芯粒之间 | 高，但低于片内 |
| **卡间** | 不同卡之间（NVLink/InfiniBand/RoCE） | 明显低于前两者 |
| **跨机** | 跨服务器（以太网/InfiniBand） | 最低 |

**关键判断**：一个模型的并行策略（张量/专家并行需要高频通信）能不能跑得动，取决于**它需要的通信量能不能被目标层级的带宽承载**。所以：

```
某并行策略是否可行 ≈ 它每步的通信量 ÷ 对应层级的互联带宽 ≤ 可接受的时间占比
```

**这就解释了为什么"超节点"这类形态存在**：把更多卡拉进同一个高速域，可以让更激进的并行策略变得可行。**互联拓扑不是配套设施，而是决定能跑什么算法的前提。**

## 五、能效：为什么它比算力更能说明问题

**能效（每瓦性能）**是数据中心真正在买的指标——因为功耗同时绑定电费、散热能力和机柜密度。有三个层次要分清：

| 指标 | 含义 | 陷阱 |
|---|---|---|
| **峰值能效** | 标称算力 ÷ TDP | 分子是峰值、分母是标称功耗，两个都是理想值 |
| **实际能效** | 实际吞吐 ÷ 实际功耗 | 才是可用的数字 |
| **空闲功耗占比** | 空闲时的功耗 ÷ 满载功耗 | 常被忽略，但在集群成本里是真实开销 |

**核对能效时的两个要点**：

1. **要看"在什么负载下"**——能效曲线通常在某个负载区间最高，满载和空载都更差。声称"每瓦 X 次运算"而不说负载点是无效的。
2. **要把 TDP 理解成"散热设计指标"而不是"功耗上限"**——它的含义与实测功耗不同（见 [L0](../overview.md)）。

**一个跨层提醒**：能效不只由芯片决定，**冷却方式与供电效率也是分母的一部分**。整柜方案的电费账要算到机房层，而不只是卡上（见 [L7 的 $/百万 token](../L7-分布式与集群/01-集群评测.md)）。

## 六、怎么核对一份规格页：一份检查清单

拿到一张加速卡的规格页，按这个顺序核对，能过滤掉绝大部分误导：

| 检查项 | 要看什么 |
|---|---|
| **算力** | 精度、dense/sparse、频率条件——**四项缺一项就不能采信** |
| **显存** | 标称容量 vs 可用容量；带宽是不是按公式可验算 |
| **片上存储** | 容量与带宽**都要**；只有容量说明不了数据复用能力 |
| **互联** | 域内卡数 + 聚合带宽；不能只看"支持 NVLink"这类定性描述 |
| **功耗** | TDP 与实际功耗的区别；有没有给能效曲线而不是单点 |
| **工艺与封装** | 良率/供应相关的表述往往是新闻稿而非规格 |
| **实测口径** | 若引用跑分，**必须能追溯到模型、精度、并发与引擎版本** |

**最有用的一条纪律**：**凡是"只给一个数字、不说条件"的性能表述，都当作不成立**——这与 [L7 的评测纪律](../L7-分布式与集群/01-集群评测.md)是同一条原则，只是作用在了硬件规格上。

## 七、怎么评测才算可信

**必须固定的**：芯片型号与固件版本、**频率与功耗状态**（是否锁频、是否受功耗墙限制）、环境温度与散热条件、显存访问模式与数据布局。

**必须报告的**：算力的**完整口径**（精度/稠密或稀疏/频率）、有效带宽（而非标称）、以及功耗（而非 TDP）。

**这一层特有的坑**：

- **用峰值算力对比实测性能**：分母与分子口径不同，比出来的比例没有意义。
- **不锁频做对比**：同一张卡在不同散热条件下能差出可观比例，**不锁频的跑分不可比**（这条与 [L5](../L5-编译器与算子/01-编译与算子指标.md) 一致）。
- **用标称带宽算理论最优时间**：实际达不到，会得出"实现有问题"的错误结论。
- **忽略容量约束**：先看跑不跑得起来，再看跑多快。
- **把"支持某互联"当成"有某带宽"**：支持是定性的，带宽才是定量的。
- **拿不同精度/稀疏口径的算力互相比较**：这是规格页对比中最常见的作弊方式。

## 八、一张表：该看哪个指标

| 你要回答的问题 | 该看的指标 |
|---|---|
| 这颗芯片算力多高 | 峰值算力 **+ 精度 + dense/sparse + 频率条件**（缺一不可） |
| 为什么实际达不到峰值 | 有效带宽、算术强度拐点（去 [L5](../L5-编译器与算子/01-编译与算子指标.md) 看利用率） |
| 模型装得下吗 | 可用显存容量 vs（权重 + KV cache + 激活 + 开销） |
| 带宽够不够 | 自行验算的显存带宽 + 目标访问模式下的有效带宽 |
| 多卡能扩到多少 | 各层级互联带宽（片内/D2D/卡间/跨机）+ 并行策略的通信量 |
| 值不值这个电费 | 实际能效（在给定负载点）+ 空闲功耗占比 |
| 宣传数字可信吗 | 第六节那份检查清单 |
