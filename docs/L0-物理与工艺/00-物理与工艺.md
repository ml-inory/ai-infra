# 物理与工艺：能不能造出来

> **这一层在讲什么。** 上面几层都在讨论"这块芯片能做什么"；这一层只回答一个问题：**它能不能被造出来，造出来能不能稳定工作。**
>
> 这一层的关键在于**约束是从物理来的，不是从设计来的**。前面每一层都可以通过写软件、改架构来绕过限制，**只有这一层的限制绕不过去**——光速、热力学、良率曲线，都是给定的。
>
> **本文建立概念，不追求精确。** 想知道"这些物理量怎么影响选型"，看 [01-工艺与物理指标](01-工艺与物理指标.md)。
>
> **和上一层的关系。** [L1](../L1-芯片与硬件/00-芯片与硬件.md) 讲的是芯片"长什么样"（算力、存储、互联）；这一层讲的是它"为什么长成这样"——**很多架构选择其实是被制造与物理逼出来的**（例如为什么要做芯粒、为什么带宽涨得比算力慢）。

---

## 一、工艺节点：名字与实物已经脱钩

"5nm / 3nm / 2nm"这类数字**曾经**对应真实的物理尺寸（栅极长度或某个特征尺寸）。但今天它更多是一个**营销与技术代际的标签**：

- 不同代工厂的"3nm"在物理密度上并不相同；
- 节点数字**不再等于任何单一物理尺寸**；
- 真正决定能力的是一整套指标：**晶体管密度、性能、功耗、以及 SRAM 面积**。

**这对上层的实际影响**：**不能靠节点数字推断能力**。想知道"换到新节点能带来什么"，要看具体工艺的平台数据，而不是看那个数字变小了。

**还有一个容易被忽略的事实**：**SRAM 面积缩小得比逻辑慢**。所以随着节点推进，**在片上加缓存越来越不划算**（面积成本高）——这正是芯片厂商不断把缓存往外搬、往 HBM 走的原因之一，也是"chiplet"路线的一个动因。

**工艺选择因此是一个三方权衡**：先进节点（性能/功耗好，但贵、SRAM 不划算、产能紧张）vs 成熟节点（便宜、产能足、SRAM 划算）。

## 二、先进封装：这一层最现实的瓶颈

当单块硅片做到极限（受**掩模尺寸**限制，也受良率限制），继续扩大的唯一办法是**把多块芯片封装在一起**。这就是先进封装在今天的地位：**它已经从"配套工艺"变成了决定产品上限的关键环节**。

### 2.1 三种典型做法

| 做法 | 思路 | 特点 |
|---|---|---|
| **2.5D（硅中介层）** | 多块芯片并排放在一块中介层上，中介层提供高密度走线 | 芯粒间带宽高、成熟；成本与产能是主要约束 |
| **3D（堆叠）** | 芯片垂直堆叠，用硅通孔连接 | 距离最短、带宽最高；**散热是最大难题**（热量被夹在中间） |
| **有机基板 / 桥接** | 用基板或局部桥接提供互连 | 成本低、面积大；互连密度低于硅中介层 |

**选择的核心矛盾是"互连密度 vs 成本与散热"**：想要更高带宽就必须让芯粒靠得更近、走线更密，而这同时带来成本上升和散热困难。

### 2.2 为什么要做芯粒：良率的数学

**芯粒路线最硬的动机是良率。** 芯片制造不可避免地有随机缺陷，缺陷密度固定时，**面积越大、良率下降得越快**（缺陷数随面积线性增长，而无缺陷的概率随面积指数下降）。

所以：

```
把一块大芯片拆成几块小芯片
  → 每块小芯片的良率显著提高
  → 只有"好的小芯片"才进入封装
  → 整体可用硅面积的成本大幅下降
```

**这个数学关系解释了今天的一切"拼装式"设计**：不是工程师喜欢拼，而是大芯片在经济上不可行。

**代价是"封装良率"变成了新的风险点**：多块芯粒封装在一起，**任何一块有问题都可能导致整个封装报废**（除非能测试后再封装）。所以先进封装的**测试策略**（先测后装、已知合格芯片）和产能，常常是整个产品交付的瓶颈。

### 2.3 产能：被忽略的现实约束

**先进封装的产能往往比晶圆产能更紧张**——它涉及更复杂的设备与工艺步骤，扩产周期长。这造成一个反直觉的现象：**逻辑芯片的产能可能充足，但整卡交付仍然受限**。做选型与供应评估时，这是一个必须问的问题。

## 三、SerDes：芯片之间那条"物理通道"

芯片之间、卡之间、机器之间要通信，最终都要靠 **SerDes**（串行器/解串器）：把并行的数据转成高速串行信号发出去，在另一端再还原回来。

**为什么必须串行**：并行接口在高速下会遇到**走线之间的时序偏移与串扰**问题，速率越高越严重。串行 + 差分信号能更好地对抗这些物理效应——**这是"用复杂度换速率"的典型交易**。

### 3.1 编码效率：一个能直接算的账

早期的高速串行链路需要在数据里插入额外比特来保证**时钟恢复**与直流平衡，于是**有效带宽打了折扣**；后来的编码方式把开销大幅降低。

**这件事为什么重要**：规格页上写的"每 lane X GT/s"是**信号速率**，而**有效数据带宽 = 信号速率 × 编码效率**。忽略编码效率会高估约 20% 的带宽。**不同代的接口编码方式不同，所以"每 lane 速率翻倍"不等于"带宽翻倍"。**

### 3.2 距离：铜的物理极限

**SerDes 的速率与传输距离是一对矛盾**：速率越高，信号在铜缆/PCB 上衰减越快、可传输距离越短。

这解释了一个重要的系统现象：**"在机柜内用铜、跨机柜用光"不是偏好，而是物理决定的**。想在不增加距离的前提下提高总带宽，只能**增加 lane 数**（更宽的接口、更多的线）或**中继**。

### 3.3 链路不是无错的：FEC 与重传

高速链路的误码率不可能是零。应对方式有两类，**它们的取舍很不一样**：

| 机制 | 做法 | 特点 |
|---|---|---|
| **前向纠错（FEC）** | 发送端加校验冗余，接收端自行纠正 | **无需往返**、延迟稳定；但消耗带宽、且纠错能力有限 |
| **重传（retransmission）** | 检测到错误后请求重发 | 不消耗额外带宽；但**引入往返延迟**、且需要缓冲 |

**这组取舍在系统设计里反复出现**：以太网倾向 FEC，而某些低延迟总线倾向 CRC + 重传（因为可以做到"极低概率重传"，平均延迟不受影响）。**选互联方案时要问的正是"错误恢复的方式与它带来的延迟特性"。**

## 四、信号完整性与供电：两个"看不见"的工程

### 4.1 信号完整性（SI）

高速信号的敌人有三个：**反射**（阻抗不连续导致能量弹回）、**串扰**（相邻走线互相干扰）、**抖动**（时序不确定）。

**它们共同的效果是"眼图变小"**——即接收端能可靠判别的窗口变窄。所以高速设计里有一整套手段（阻抗匹配、差分对、均衡、走线约束）来保住眼图。

**对上层的实际影响**：**PCB 与连接器的质量会直接决定链路能不能跑在标称速率上**。同一块卡插在不同品质的机器上，实际可用带宽可能不同。

### 4.2 供电（PI）

现代加速卡的电流非常大、电压很低、负载变化极快（计算任务来去造成电流剧烈波动）。这让供电变成一个难题：

- **大电流 + 低电压**意味着**任何一点阻抗都会造成可观的压降**；
- **负载剧变**意味着供电必须**快速响应**，否则电压跌落会导致错误甚至复位；
- 因此需要**多级供电（VRM）+ 就近去耦**：把电荷储备放在离芯片尽可能近的地方，缩短响应路径。

**对上层的实际影响**：**供电设计会限制芯片能跑多快、以及能不能瞬间升频**。这也是为什么"同样的芯片，不同板卡设计性能不同"。

## 五、ECC 与链路可靠性：不能有静默错误

数据中心设备的一条硬要求：**不能出现"静默数据错误"**（算错了但没人知道）。所以从内存到链路都要有校验。

| 层次 | 机制 | 特点 |
|---|---|---|
| **内存 ECC** | 用额外比特纠正单比特错误、检测多比特错误 | 代价是**容量与带宽开销** |
| **片上/堆叠内存 ECC** | 在内存芯片内部或堆叠内部做校验 | 对上层透明，但同样占容量 |
| **链路 CRC / 重传** | 传输层校验，出错重发 | 保证链路可靠，但引入延迟（见第三节） |

**"ECC 的代价"值得单独记住**：它**要么吃掉容量、要么吃掉带宽**，而且这个代价会一路传到上层——**规格页上的"标称容量"与"可用容量"之间的差额，一部分就是它**。

## 六、功耗与散热：这一层最硬的约束

功耗不是"性能的副产品"，而是**决定系统形态的第一约束**。

### 6.1 为什么功耗随频率急剧上升

```
功耗 ≈ 动态功耗（与 电压² × 频率 × 电容 相关）+ 静态功耗（漏电，随温度上升）
```

要提高频率就必须提高电压，而**动态功耗随电压的平方增长**。所以"频率提高 20%"可能带来"功耗提高 50%"以上——**这就是为什么不能简单靠超频解决问题**。

**另一个正反馈藏在温度里**：温度升高 → 漏电增加 → 功耗增加 → 温度进一步升高。**散热不足会导致性能持续下降，而不是稳定在某个水平。**

### 6.2 散热能力的量级决定了系统形态

**风冷的散热能力有物理上限**（靠空气的比热与流量），超过某个功率密度就必须换液冷。这不是"液冷更好"的偏好问题，而是**每机柜功率超过某量级后，风冷在物理上做不到**。

这直接决定了 [L7 的集群形态](../L7-分布式与集群/00-集群是什么.md)：**超节点整机柜为什么普遍是液冷**——不是因为它高级，而是因为那个功率密度风冷压不住。

### 6.3 TDP 的正确理解

**TDP 是散热设计指标**（"系统要按这个功率准备散热能力"），**不是芯片的实时功耗上限**。实际功耗会随负载与频率动态变化，可能低于也可能（在短时加速时）高于 TDP。

**对上层的实际影响**：**按 TDP 估算电费与散热需求会系统性地偏**，真实的账要按实测功耗曲线算（见 [L1 的能效指标](../L1-芯片与硬件/01-芯片与硬件指标.md)）。

## 七、这一层如何反推上面的所有层

最后梳理一次"物理如何决定架构"，这也是理解这一层价值的最好方式：

| 物理约束 | 逼出来的架构选择 |
|---|---|
| 大芯片良率随面积急剧下降 | **芯粒（chiplet）路线**、先进封装成为关键工艺 |
| SRAM 面积随节点缩小变慢 | 缓存往外搬、HBM 容量成为关键指标 |
| SerDes 速率与距离矛盾 | 机柜内铜、跨机柜光；超节点把距离压到最短 |
| 链路误码不可避免 | FEC 与重传的取舍；互联方案在延迟与带宽间选择 |
| 功耗随频率超线性增长 | DVFS、功耗墙、液冷、以及"能效优先"的选型逻辑 |
| 散热能力上限 | 整柜液冷、机房改造成为部署前提 |

**一句话总结这一层**：**上面所有层的自由度，都是这一层"允许"的。** 所以评估一个技术方案时，如果它在物理上不合理，那它一定不会成立——**不管软件层描述得多好**。
