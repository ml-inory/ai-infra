怎么读这张表。L7 的四个关键指标是集合通信带宽、通信占端到端时间的比例、扩展效率、故障恢复时间（MTTR）。 厂商在发布会里通常只给前两个的“分母”（互连带宽、算力、容量），真正的扩展效率要靠 MLPerf / 第三方基准或客户实测。 本页把「官方宣称」和「第三方实测」分开标注，避免把 PPT 数字当成绩效。

Blackwell Ultra，2025 起量，当前出货主力
规格官方 价格估算
形态单机柜 72 × Blackwell Ultra GPU + 36 × Grace CPU，全液冷

  • MLPerf v6.1（2026-09）DeepSeek-R1 offline：72 卡 679,740 tps → 288 卡 2,705,130 tps，≈99% 扩展效率
  • 官方：TPS/MW 比 Hopper 代高 5×
  • 注意：99% 是同一套 4 机柜内的横向扩展，跨集群仍看网络

NVIDIA · Groq 3 LPX 机柜

2026 H2 与 Vera Rubin 同期出货；SRAM 路线的“官方收编”
规格官方 价格未公开
形态液冷 LPX 机柜，256 颗 Groq 3 LPU（每托盘 8 颗）
存储单颗 500 MB SRAM；整柜 128 GB SRAM（对比：单颗 Rubin 有 288 GB HBM4）
带宽单颗 22–150 TB/s 级；整柜 scale-up 640 TB/s
价格未公开。背景：NVIDIA 以约 $20B 的“准收购”方式拿到 Groq 技术与团队（非正式并购）

关键指标

  • 极低延迟解码：官方称可达数千 tokens/s/用户
  • 代价是每芯片 t/s 经济性很低，必须成柜部署
  • 定位是 GPU 的补充，而非替代

典型负载

  • 解码阶段、权重驻留 SRAM 的推理
  • 与 Rubin NVL72 搭配：GPU 做 prefill/softmax/路由，LPU 专注低延迟生成
  • 不适合大 batch 高吞吐场景

效率

  • NVIDIA 自己承认“75% 用例中几乎无增益”
  • 后续 LPU 35 / LPU 40 才逐步 NVLink 化、支持 NVFP4
  • 选购逻辑：只有当延迟 SLO 无法用 GPU 满足时才值得

NVIDIA · DGX B200 / HGX B200（8 卡节点）

集群的“最小积木”，也是多数客户真正买得起的单位
规格官方 价格估算
形态8 × B200 GPU，单机 8 卡 NVLink 域，可堆成 SuperPOD
显存180 GB HBM3e / 卡，整机约 1.4 TB
算力约 72 PFLOPs FP4 dense / 机（8 × 9 PF 级）
价格整机约 $0.5–0.7M 量级（第三方估算，随 HBM 行情波动大）

关键指标

  • 8 卡 NVLink 域：单节点内通信不占网络带宽
  • 跨节点必须靠 InfiniBand / Spectrum-X，通信占比会明显上升
  • SuperPOD = 用同一套节点 + 网络 + 存储拼出千卡级集群

典型负载

  • 中等规模微调、RAG、推理服务
  • 大集群的构建单元

效率

  • 扩展效率对网络极敏感：节点内接近线性，跨节点普遍掉到 80–90%
  • 选它还是选整机柜，本质是“要不要用功率和液冷换通信占比”
来源：NVIDIA DGX 产品页（规格）；价格为 2026 年第三方行情汇总，仅供量级参考。

DeepSeek-R1 671B：prefill 与 decode 实测数据

先回答有没有：有，而且是分阶段的。SemiAnalysis 的 InferenceX 把 DeepSeek-R1-0528（671B，MoE + MLA）的 prefill 吞吐与 decode 吞吐分别按阶段归一化后公开，含 2025-12 → 2026-09 的 1,310 条原始压测记录，覆盖 GB300 / GB200 / B300 / B200 / H200 / H100 / MI355X / MI325X / MI300X。下面表格直接从它的公开 API 取数计算， 不是发布会口径。华为的 384 卡超节点另有论文给了官方数字（见表 4）。

为什么 prefill 和 decode 一定要分开看

同一张卡，两个阶段的瓶颈完全不同
第三方实测 口径需对齐

prefill（吃输入）

  • 一次并行处理整段 prompt，算力密集 + 带宽混合
  • batch 一大基本能把张量核跑满，所以数字通常是 decode 的 3–10 倍
  • 决定 TTFT；长上下文时是主要成本

decode（出输出）

  • 每 token 都要读一遍激活权重与 KV，受 内存带宽支配
  • 并发越高每卡吞吐越高，但单用户速度（交互度）下降
  • 决定 TPOT / tokens/s/用户，也就是体感快慢

读数据的三个前提

  • 单位是 tok/s/卡；PD 分离时 prefill 与 decode 各按自己那部分卡数归一化
  • 必须按 交互度（tok/s/用户）对齐，否则等于拿最大吞吐比最低延迟
  • 框架（TRT-LLM / SGLang）、精度（FP4/FP8）、是否开 MTP 都会显著改变结果

选型时怎么用这些数字

1. 先看通信占比，再看峰值算力

  • 单柜/超节点的互连带宽决定“能开多大并行”
  • 跨机柜 scale-out 带宽（NIC × 端口）决定千卡后的实际效率
  • 把 集合通信时间 / 端到端时间 要到手，比看 TFLOPS 有用

2. 价格分三层看

  • 硬件 CAPEX：整柜/整机报价（多数厂商不公开）
  • 运行成本：功率密度 × 机房 PUE × 电价，整柜 120 kW 是分水岭
  • 折旧后单位成本：$/百万 token 或 $/卡·hr，才能横向比

3. 效率要找第三方证据

  • MLPerf 是当前最通用的横向坐标（v6.1 覆盖 GB300 / MI355X / 首个 Vera Rubin）
  • 厂商宣称的 “N×” 一定要问基准模型、batch、精度、是否 PD 分离
  • 同样硬件，PD 分离与否能让结论反转（见 TPU vs GB300 的例子）
